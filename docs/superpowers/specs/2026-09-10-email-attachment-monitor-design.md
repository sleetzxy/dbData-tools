# 邮件附件定时监控设计

**日期：** 2026-09-10  
**状态：** 已确认  
**范围：** IMAP 邮件附件监控（GUI 页 + core 服务 + 本机配置/去重）

---

## 1. 背景与目标

在现有「DB 数据工具集」中增加能力：定时拉取指定发件人发来的邮件，**仅下载附件**到指定本地目录，便于后续 CSV/数据导入。目标邮箱为腾讯企业邮箱等支持标准 IMAP 的邮箱；账号、密码与规则在界面可配置。

### 1.1 已确认需求

| 维度 | 选择 |
|------|------|
| 下载内容 | 仅附件，落到指定文件夹 |
| 运行方式 | 应用内「开始/停止」；按间隔轮询；关闭应用即停止 |
| 协议 | 通用 IMAP（预填腾讯企业邮默认主机/端口） |
| 发件人 | 多个地址列表（逗号或换行） |
| 扫描范围 | 最近 N 天；**不依赖**已读/未读 |
| 去重 | 本机记录（账号 + 邮件 UID + 附件名） |
| 附件过滤 | 可配置扩展名白名单（必填，空则禁止启动） |
| 同名文件 | 自动重命名（`name_1.ext`） |
| UI 布局 | 继承 `BaseToolPage` 左右分栏（左配置 / 右日志） |

### 1.2 成功标准

- 用户可在界面配置 IMAP、发件人、目录、间隔、扩展名与 N 天后，点击开始持续下载匹配附件
- 误标已读不会导致漏下；已下载附件不会重复落盘
- 配置可持久化；密码不明文存储
- 停止或关应用后监控线程结束，无僵尸轮询

### 1.3 一期明确不做

- 关闭应用后仍后台监控（系统服务/计划任务）
- Exchange/EWS 等非 IMAP 专有协议
- 保存 `.eml` 或邮件正文
- 复杂规则引擎、多监控任务并行
- 自动标已读（可选增强，非一期必须）

---

## 2. 总体方案

采用 **独立功能页 + `core` 监控服务（方案 A）**：

```
侧栏「邮件附件监控」页 (gui/pages/...)
        │ 读写配置 / 开始·停止 / 展示日志
        ▼
EmailMonitorService (core/email_monitor/)
        │ 后台线程按间隔 tick
        ▼
ImapClient → Filter → AttachmentSaver → DedupStore
        │
        ▼
ConfigManager（配置 JSON）+ 去重状态文件
```

业务逻辑在 `core/`，页面只负责表单与启停，与现有导入/导出页模式一致。

## 3. 信息架构与导航

- 侧栏分组 **「数据进出」** 下新增条目：`邮件附件监控`
- 页面 `REQUIRES_ACTIVE_CONNECTION = False`（不依赖数据库「当前连接」）
- 关应用时：若监控中，先停止服务再退出

## 4. 模块设计

### 4.1 GUI：`EmailMonitorPage`

- 路径建议：`src/gui/pages/email/monitor.py`（或同等清晰路径）
- 继承 `BaseToolPage`：左配置、右日志、配置加载/保存
- 主操作：**开始监控** / **停止**（互斥）；另提供 **测试连接**、**保存配置**
- **测试连接：** 连接 IMAP 主机 → 登录 → `SELECT INBOX` → 断开；成功/失败写入右侧日志并弹窗提示
- **开始后首轮：** 启动后**立即**执行一次 tick，再按间隔休眠循环
- 不调用基类一次性 `execute_task` 作为唯一入口；改为托管 `EmailMonitorService` 生命周期（开始=启动循环，停止=请求退出）。若与基类任务历史钩子冲突，以「长驻监控任务」方式适配：开始时 `create_task(status=running)`，停止/结束时 `update_task`

**左侧字段**

| 字段 | 默认/说明 |
|------|-----------|
| IMAP 主机 | `imap.exmail.qq.com` |
| 端口 | `993` |
| 使用 SSL | 是 |
| 账号 | 邮箱地址 |
| 密码 | 密码框；多为授权码 |
| 发件人列表 | 多地址，逗号或换行 |
| 下载目录 | 目录选择器 |
| 扩展名白名单 | 如 `.csv,.xlsx,.zip`（大小写不敏感）；**必填，禁止为空** |
| 最近 N 天 | 默认 `7` |
| 轮询间隔（秒） | 默认 `60` |

**开始监控前必填校验（任一缺失则阻止启动）：** IMAP 主机、端口、账号、密码、至少一个发件人、下载目录（存在且可写）、扩展名白名单非空、最近 N 天 ≥ 1、轮询间隔 ≥ 1 秒。

**白名单为空：** 视为配置不全，**禁止启动**，且过滤逻辑不得解释为「下载全部附件」。

**邮箱文件夹：** 一期固定扫描 `INBOX`。

**配置生效时机：** 「开始监控」时对当前表单做一次快照供本轮服务使用；运行中改表单不影响已启动的监控，需先停止再开始才应用新配置。

### 4.2 Core：`core/email_monitor/`

建议拆分（接口清晰、可单测）：

| 单元 | 职责 |
|------|------|
| `ImapClient` | 连接、登录、按日期检索、取信、解析附件；标准库 `imaplib` + `email`；附件以 `Content-Disposition: attachment`（或带文件名的附件 part）为准，跳过纯内联图/签名图 |
| `filters` | 发件人集合匹配；扩展名白名单 |
| `saver` | 写文件；同名自动 `_1`、`_2`… |
| `dedup` | 持久化已处理键：`account + mailbox_uid + filename`（账号参与键，避免换号后 UID 碰撞误跳过） |
| `service` | 后台线程循环：校验 → tick → 休眠；支持协作式 stop |

依赖：一期 **不新增** 第三方邮件库；沿用标准库。

### 4.3 配置与安全

- 配置文件：如 `~/.dbdata_tools/email_monitor.json`（与现有 `ConfigManager` 风格一致）
- 密码：落盘前加密（可复用或对齐项目内已有敏感字段处理方式；若无现成方案，使用本机密钥派生的对称加密，密钥不入库明文）
- 去重状态：独立 JSON/小型 store，路径与配置同目录或可配置旁路文件

### 4.4 运行行为（单次 tick）

1. 连接 IMAP（失败则记日志并计入连续失败）
2. 检索最近 N 天邮件（SINCE 日期；不按 UNSEEN）
3. 过滤发件人 ∈ 配置列表
4. 遍历附件；扩展名 ∈ 白名单
5. 若去重键（account + UID + filename）已存在则跳过
6. 保存到下载目录（处理重名）
7. 写入去重记录；日志输出结果摘要
8. 成功则清零连续失败计数

## 5. 错误处理

| 场景 | 行为 |
|------|------|
| 配置不全 / 目录不可写 / 白名单为空 | 开始前按 §4.1 必填清单校验，阻止启动并提示 |
| 单轮登录/网络失败 | 打日志，本轮跳过，下轮继续 |
| 连续失败 ≥ 5 次 | 自动停止监控并弹窗提示 |
| 单封/单附件解析或写盘失败 | 记日志，继续处理其余 |
| 用户停止 / 关应用 | 协作停止线程，释放 IMAP 连接 |
